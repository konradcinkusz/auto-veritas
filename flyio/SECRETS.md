# Secrets

What is a secret, where it lives, and how it is set. The litmus test: anything you
would not paste into a public PR is a secret; everything in a `fly.toml` `[env]`
block is public (visible in `fly config show` and image metadata).

## Root secrets (GitHub **Environment** `flyio`, set once by a human)

| Name | What it is |
|---|---|
| `FLY_API_TOKEN` | From `fly tokens create org`. A GitHub *Environment* secret, not a repository secret, so it can be reviewed and restricted. |
| `POSTGRES_PASSWORD` | The one database password. Alphanumeric only — `+ / = ;` break connection strings and YAML a rotation later. |
| `JWT_SIGNING_KEY_PEM` | The RS256 private key for **this system's** authservice instance: PKCS#8, 2048-bit minimum, generated by `scripts/generate-jwt-key.sh` run once for production and pasted here. Never the local dev key, never reused by any other system. |
| `INITIAL_ADMIN_PASSWORD` | The seeded SuperAdmin's password (the owner's agent account). |

## Derived secrets (assembled by `.github/workflows/flyio.yml`, staged per app)

| App | Secret | Derived from |
|---|---|---|
| `auto-veritas-postgres` | `POSTGRES_PASSWORD` | root secret |
| `auto-veritas-authservice` | `ConnectionStrings__DefaultConnection` | password + `auto-veritas-postgres.internal:5432/authdb` |
| `auto-veritas-authservice` | `Jwt__PrivateKeyPem` | root secret |
| `auto-veritas-authservice` | `InitialAdmin__Password` | root secret |
| `auto-veritas-offers` | `ConnectionStrings__DefaultConnection` | password + `auto-veritas-postgres.internal:5432/offersdb` |

The web app holds no secrets: sessions live in HttpOnly cookies signed by nobody —
the tokens inside them are authservice's, verified against its JWKS.

## Rules

- Secrets are set with `fly secrets set --stage` **from CI only**; a secret set by
  hand on one app and forgotten is how environments diverge.
- Rotating the signing key is a *rolling* rotation: set the new key as
  `Jwt__PrivateKeyPem`, move the old **public** key to `Jwt__PreviousPublicKeyPem`,
  keep it for one access-token lifetime (60 min), then drop it. Dropping it
  immediately signs every user out.
- A secret that lands in git history is rotated FIRST, scrubbed second.
- The deploy workflow fails if the published JWKS is empty after an authservice
  deploy — a missing key silently selects HS256 and serves `keys: []` while every
  consumer rejects every token.
